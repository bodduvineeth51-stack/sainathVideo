## Finishing steps (once the footage is reachable)

```bash
scripts/fetch_footage.sh                                   # → source/raw.mp4 (read-only), prints specs
pip install faster-whisper==1.1.1
python3 scripts/transcribe.py source/raw.mp4 work/         # word timestamps
python3 scripts/propose_edl.py work/transcript.json reel/src/edit/edl.json
#   review reel/src/edit/edl.json: delete weaker retakes, keep dialogue order
python3 scripts/cut.py reel/src/edit/edl.json reel/public/footage/talking_head_cut.mp4 --fps <source fps>
python3 scripts/retime_transcript.py work/transcript.json reel/public/footage/talking_head_cut.mp4.map.json work/transcript_cut.json
#   set shot start/end, beats and captions in reel/src/edit/timeline.json from work/transcript_cut.json
#   set ramScreenSide + hands from the footage (see "Hand mapping")
cd reel && npm run preview && npm run final                # → out/reel_final_1080x1920.mp4, validated
```

`render.sh final` encodes H.264 High / yuv420p / AAC 320k / 48 kHz and loudness-normalises to −14 LUFS, −1 dBTP. `validate.sh` then decodes the whole file, checks the streams, measures loudness and exports one still per shot to `out/review/`.

```
audio/gen_sfx.py            original SFX + music synthesis
scripts/                    footage pipeline, render, validate
```

Every scene is also its own composition (`Scene-s07-lakshman`, …) for review in isolation. SFX cues are stored relative to their shot, so retiming a shot moves its sound with it. Beats inside a shot (e.g. when you say "authentication") are stored in seconds and drive the animation.

## Design system

Off-white `#F2EEE6` and charcoal `#16171A`, plus two accents that double as character colours: **Ram = slate blue `#6F8FC9`**, **Lakshman = amber `#E9A23B`**. Amber also marks "the structured approach" all the way through, from Lakshman's spec to the process, architecture and review scenes. The kingdom scenes use a dusk palette with the same accents. Type is Space Grotesk (display, true extruded 3D), Inter (UI and subtitles) and JetBrains Mono (code, ligatures off so `<=` reads literally). There are no glows or particles, and the only gradient is the dusk sky in the kingdom scenes.

## Decisions and assumptions to confirm

1. **Hand mapping.** Your left hand is Ram. In unmirrored footage your left hand appears on the viewer's *right*, so `ramScreenSide` defaults to `"right"`. Every Ram/Lakshman layout (hand labels, split screens, comparison, Ram's reveal in the victory scene) follows this one value. It must be checked against the real footage. The footage itself is never flipped.
2. **The app-builder interface is generic and unbranded.** It's labelled "AI App Builder · illustration", not made to look like Lovable. Your voice names the tool; the visual doesn't pose as a screenshot of it.
3. **Example app content.** The brief doesn't say which app the brothers build. Lakshman's spec uses a neutral team-tasks app (problem, users, features, email/password sign-in, colours/type, hierarchy, structure, validation). Scene 16's bug ties back to it: the spec says "due date today or later", the AI-written code uses `<=` and rejects today, a test catches it, and it's fixed to `<`.
4. **Comparison (scene 8).** The comparison shows what each brother specified (1 line vs 9 sections, login yes/no, and so on). It has no scores, ratings or benchmarks.
5. **Captions.** The subtitles are written only for the lines quoted in the brief, and those translations still need checking against your exact words. "Syntaxes nerchukokandi" is subtitled "Don't just learn syntax", matching your stated intent rather than the literal "don't learn syntax". The lines I haven't heard (the father's challenge, Ram's and Lakshman's descriptions) have **no captions yet**. I won't caption speech I haven't heard. The title shot has no subtitle because the 3D title already shows that line.
6. **Timings** in `timeline.json` are a draft (about 90 s). The real cut length comes from your delivery.
